Two things to understand first

Two different domain jobs

Vercel made your site load at your domain. This makes your emails send from your domain. Same domain, a different set of DNS records. That's called email authentication.

The API key + the webhook

The API key is the login that lets your app add people to Systeme.io. The webhook is the trigger that fires when someone pays. Together: pay → tag → welcome email.

1

Authenticate your domain for email

This lets Systeme.io send email from you@yourdomain.com instead of a generic address.

  • In Systeme.io: Settings → Custom domains (or Emails)
  • Add the domain you bought in Video 1
  • Systeme gives you a few DNS records (mostly CNAMEs, plus a DMARC record), add exactly what it shows you
  • Add those records at your domain provider (where you bought the domain), then come back and verify
Important: this is NOT the same as connecting your domain to Vercel. Vercel made your site live. This is a different set of records that lets Systeme.io send email from your domain. Same domain, different job.
👉 What this is called: email authentication. The records prove your mail is really from you, mainly DKIM (the _domainkey signature records) and DMARC (protects your domain from being spoofed). Systeme.io gives them as CNAME and TXT records, just copy exactly what it shows.
✓ Done when: Systeme.io shows your domain authenticated / verified.
2

Set your professional sending address

  • In Systeme.io: Settings → Emails → set your "from" address, e.g. hello@yourdomain.com
  • Now every email comes from you, not a random address, which is what keeps you out of spam and looks legit
👉 This sends from your domain. If you want to receive replies at that address, you'd add a mailbox like Google Workspace later. Not needed today.
3

Create your Systeme.io API key and add it to Vercel

  • In Systeme.io: Settings → Public API Keys → create a key and copy it
  • In Vercel → Settings → Environment Variables, add it as SYSTEME_API_KEY and save
👉 This is the "API" piece. The key is what lets your platform add and tag contacts in Systeme.io. It's a secret, so it lives in Vercel, never in your code.
✓ Done when: SYSTEME_API_KEY is saved in Vercel.
4

Connect Stripe so every payment tags them

You don't build this by hand. Paste this into Claude and let it build the connection:

Paste into Claude
When someone purchases a subscription on my platform through Stripe, add their email to Systeme.io as a contact and tag them "Member" (or whatever tag I choose), so I can trigger a welcome-email automation off that tag. Add this to my existing Stripe webhook handler, don't create a second one. Stripe is already set up and its keys are in Vercel, reuse the existing setup. Read the Systeme.io API key from an environment variable named SYSTEME_API_KEY, which I've already added in Vercel. Handle the case where the contact already exists. Check the current Systeme.io API docs first so the endpoints are right, and don't ask me questions, make reasonable choices yourself.
👉 Your Stripe webhook was already set up in Week 3, and your key is already in Vercel from Step 3, the tagging just gets added to your existing setup. Nothing new to do in Stripe.
Redeploy once Claude pushes it. Environment variables only take effect on a new deployment, so after it's built, redeploy in Vercel and your key kicks in.
✓ Done when: Claude confirms it's built and pushed, and you've redeployed.
5

Build the welcome automation

Now the tag needs to actually do something. Set up the automation in Systeme.io:

  • In Systeme.io: Automations → Rules → Create
  • Trigger: "Tag added" → your tag (e.g. Member)
  • Action: "Send email" → your welcome email
  • Write a short, warm "Welcome to the community" email, what they get, and their first step
👉 The tag is the bridge. Stripe tags them, and the tag triggers this email. That's the whole loop.
✓ Done when: adding the tag to a test contact sends you the welcome email.
6

Test it, end to end

  • Go to your live site and run a $0 test signup (use the 100%-off coupon you made in Video 2)

A green build proves nothing. The only proof is a real signup that ends with the welcome email in the inbox. Do that before you call it done.
