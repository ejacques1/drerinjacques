Friday Live — What I Built

What I built with AI: seven real case studies.

Today you'll see how I used AI to build a free signup page, a paid registration process, a transformed video, a purchasing comparison, automatic coaching routing, a provider training experience, and a full college course hub. Each one comes with the finished result, the workflow, and the exact prompts behind it.

Start here — one foundation for the first two

Set this up once.

Case Study 1 (free resource) and Case Study 2 (paid registration) start from the same website foundation. Do this once, then pick either one. You don't have to build Case Study 1 before Case Study 2.

  1. Install and sign into the Codex or Claude desktop app.
  2. Create a project folder on your computer and open it in the AI app.
  3. Create a GitHub repository and connect the folder to it.
  4. Go to vercel.com/new, import the repo, and deploy.
  5. Create a free Systeme.io account and create the tag the case study needs.
  6. Create a Systeme.io API key and save it privately in Vercel as SYSTEME_API_KEY.
Choose what to build: Case Study 1 collects an email before opening a free resource. Case Study 2 collects an email and payment for a paid offer. Stripe is added only for the paid workflow.

Mac training: a paid registration process

Show: drerinjacques.com/mac-training

You can start here. Do the shared setup above, create the Mac Training tag in Systeme.io, and gather the offer details: title, price, date, instructor, description, what buyers receive, and what happens after payment. You don't need to build Blackwell first.

Workflow: Paid registration page → Stripe Checkout collects email + payment → Stripe verifies payment → Systeme.io contact + Mac Training tag → confirmation, Zoom info, reminders.

Stripe setup used here: sign into the Stripe dashboard in a browser, then give the AI browser access so it can help create the $25 payment setup and a testing promo code. This uses Stripe's website and does not require a Stripe MCP.

Teaching prompt — reusable wording
Build a registration page for my $25 Mac class with Dr. Vincent Jones II. I will sign into Stripe in my browser and give you browser access to help me create and connect the checkout. Save confirmed buyers in Systeme.io with the Mac Training tag. Show me a preview, guide me through any setup I need to complete, and use verified Stripe payment notifications to trigger registration. Buyers should receive the Zoom details by email; tell me what email automation still needs setting up.
👉 Proof: a completed checkout, the matching contact and tag, and the session email. A success page alone is not proof of payment. This class promises the Zoom link by email before the session, not an immediate protected Zoom-page unlock.

Video: give AI an exemplar, build your own

Show: the video whose style I liked, its AI style breakdown, my raw footage, one still-image option, and the finished Wharton edit. See the example on Instagram (the video that opens with "CHATGPT FEELS LIKE LEARNING" / "Wharton research").

Put a completed video you like in a folder the AI can access (the reference, not your own footage). The AI can use FFmpeg/FFprobe to detect scenes and pull frames, OCR to read on-screen text, and Whisper to make a timestamped transcript, so it can study composition, colors, fonts, captions, pacing, and timing.

Prompt 1 — analyze the exemplar
Analyze the reference video in this folder. Check whether you have the tools needed to inspect the video, extract frames, read its on-screen text and transcribe its audio. If anything is missing, explain it in plain language and guide me through installing it. Do not edit anything yet. Create a timestamped breakdown of the hook, spoken message, scenes, images, on-screen text, colors, fonts, layout, transitions and pacing. Explain the visual system clearly enough that we can apply the same approach to a different video without copying its exact content.

Then add your own footage to the folder, labeled clearly (e.g. REFERENCE-VIDEO.mp4 and MY-RAW-FOOTAGE.mp4).

Prompt 2 — create the editing plan
Now analyze MY-RAW-FOOTAGE.mp4. Use the style breakdown from the reference video, but use my topic, identity and content. Identify the strongest hook, map the spoken content by timestamp, list every image, logo, screenshot, headline or other asset the new edit needs, and tell me which assets already exist and which ones need to be found or created. Do not render the full video yet.
Prompt 3 — show stills before rendering
Create still-image mockups of the most important scenes using my real video frame. Preserve my face, body, clothing and setting. Show me the opening hook and each major visual treatment before you edit the full video.
Iterate one change at a time
Keep everything I approved. Change only [DESCRIBE THE ONE THING TO CHANGE], then show me another still image before rendering the video.
Prompt 4 — render the approved video
Apply only the approved visuals and text to my raw footage. Preserve my original voice, timing and identity. Export the complete vertical MP4, then verify every name and caption, the visual timing, dimensions, video playback and original audio.
👉 Check the subject's age, identity, setting and visual accuracy before using any AI-created image. The AI reverse-engineers the exemplar's approach, then builds a new edit around your real performance and footage.

Equipment research: a wish list into a purchasing comparison

Starting point: a broad equipment wish list. Through conversation I explained how I actually work, running several apps, testing local AI models, storing large files, and using multiple screens.

Workflow: Describe how it'll be used → clarify workloads, budget, priorities → narrow specs → check compatibility → research exact part numbers across vendors → compare prices/availability → revise as preferences change → total it → produce a comparison sheet and purchasing PDF.

The finished document held 14 exact products with quantities, part numbers, vendor links, unit prices, line totals, and cautions. The Sept 16, 2026 snapshot totaled $18,331.29 before tax, shipping, installation and coverage.

Prompt 1 — clarify the need first
Help me turn a broad equipment wish list into a purchasing plan. Ask me focused questions about how I work, the applications I run together, whether I want to run local AI models, file-storage needs, the number and arrangement of screens, workspace limitations, compatibility requirements, budget and priorities. Help me separate requirements from preferences before recommending specific products.
Prompt 2 — research exact products and vendors
Use the requirements we approved to create an exact equipment list with quantities, specifications and part numbers. Research the same configuration across multiple independent vendors. For each listing, record the source link, unit price, line total, availability and any concern about the configuration, seller or delivery. Do not substitute a different model without telling me, and do not treat a missing price as zero. Flag anything that needs confirmation before purchase.
Prompt 3 — revise as decisions change
Update the recommendations using my latest decisions. Recheck compatibility across the computers, displays, mounting equipment, storage and accessories. Show what changed, why it changed and how it affects the total budget. Preserve the approved specifications unless I explicitly change them.
Prompt 4 — create the purchasing document
Turn the approved research into a clear comparison sheet and PDF purchasing document. Group related equipment, preserve clickable vendor links, show quantities, unit prices, line totals, availability notes and a complete total. Include the date of the price research, assumptions, exclusions and every item that still needs verification. Check the calculations and visually inspect every page before giving me the final PDF.
👉 Before purchasing: refresh every price and availability, confirm configs with the seller, and get formal quotes when required. The document is a dated research comparison, not a current quotation.

Coaching: route each request to the right coach

Live: earlyscholars.org/coaching

The goal: a coaching program with five coaches. Every registration had to reach me and my team plus the specific coach the family chose, with no manual forwarding, no paid form service, and no parent accounts.

Workflow: Parent completes the form → it posts to a Google Apps Script web app → the script emails me and my team → it looks up the chosen coach and CCs them → the parent gets a friendly confirmation.
Prompt 1 — audit the current setup
Help me determine whether this website form already connects to a Google Apps Script web app. Inspect the form code and identify its submission URL. Then guide me through finding the matching Apps Script project in my Google accounts. Do not create a new script or deployment until we confirm whether an existing one should be updated.
Prompt 2 — build the email router
Write or update a Google Apps Script web app that receives a POST from my website's coaching registration form. It should always email my core team at [TEAM EMAILS]. If the form includes a selected coach, CC that coach using an editable name-to-email directory stored only in the script. If a coach's email is blank, send the request to the core team without CC'ing that coach. Include a friendly auto-reply to the parent's email. Validate the required fields, escape submitted content safely and add basic spam protection. Give me the complete script and explain every setting in plain language.
Prompt 3 — preserve the existing URL when updating
This form already uses an Apps Script deployment. Update the existing script without changing the website's /exec URL. After editing and saving the code, guide me through Deploy → Manage deployments → Edit → Version: New version → Deploy. Confirm that the deployment URL remains the same before we change anything on the website.
👉 What tripped me up: my routing script already existed under one Google account, named "Untitled." The right task was to update that project, not create a second deployment with a new URL. Deploy as a web app with Execute as: Me and Who has access: Anyone. Then test No preference and each coach.

Provider training: a missing video into a searchable curriculum

Public: earlyscholars.org/coach-training

Protected provider portal: earlyscholars.org/provider/mittal/training (I'll enter the access code live; it's not in this guide).

The challenge: I knew the date the training happened, but not the video's filename, whether it was renamed, or its folder. AI searched my computer using the date, found the recording, and turned it into a usable training resource, plus a public coach page separate from the licensed curriculum.

Prompt 1 — locate the missing recording safely
Help me find a training video that was recorded on or around [DATE]. I do not know its filename, whether it was renamed, or which folder it is in. Search this computer for video files connected to that date, then use the file dates, duration and sample frames to identify the most likely recording. Do not move, rename or delete anything. Show me the likely matches so I can confirm the correct video before you use it.
Prompt 2 — transcribe and create chapters
Transcribe the confirmed training video with timestamps. Review the transcript and divide it into clear chapters based on topic changes. Give every chapter an accurate, plain-language title and starting time. Create a complete transcript file and a timestamp list that can be connected to the video player so selecting a chapter starts the correct section.
Prompt 3 — build the public coach-training page
Build a polished public training page for coaches using this video, transcript and chapter list. Include the video player, training title, date and duration, presenter profile and photo, downloadable video and transcript, clickable chapter timestamps and an expandable full transcript. Keep licensed curriculum files off this public page and direct authorized users to the curriculum portal provided by their program administrator.
Prompt 4 — add it to the protected provider portal
Add the approved training experience to the existing protected provider portal without weakening or replacing its current access controls. Include the curriculum overview, implementation guidance, training recordings, clickable chapters, transcripts, downloads and coach resources in a clear order. Reuse the portal's visual style and navigation. Do not expose the access code or protected file locations in public code, page text or documentation. Show me a preview and an inventory of every file and link before publishing.
👉 The public page: a 27-minute walkthrough with Hillary Jacques, presenter profile, downloads, clickable chapters, expandable transcript, no licensed files. The protected portal: full curriculum, week-by-week guidance, syllabi, recordings, transcripts, and coach resources for authorized providers only.

PH 320: a syllabus into a student course hub

Live: ph320.vercel.app

The goal: one clear place for students to understand the course, see each week, and open the lessons, activities, assignments, datasets and documents they need, no digging through emails or scattered folders.

Workflow: Give AI the syllabus and files → explain how the class is organized → identify what students need most → build the homepage and navigation → build the syllabus and weekly pages → connect each asset where students need it → preview → correct → publish and update all semester.
Prompt — create the student course hub
Turn the syllabus and course materials in this folder into a student course hub. Create a homepage that explains the course in plain language, shows students what we are doing this week and gives them easy access to the syllabus, weekly lessons, activities, assignments, documents and dataset. Create a consistent page for each week with the date, topic, class agenda and links to everything students need. Show future weeks as "Coming Soon" until their materials are ready. Make the site clear, mobile-friendly and easy to scan. Do not invent missing policies or course information. Tell me what is missing and show me a preview before publishing.
👉 One dependable link for students, updated as the semester moves. Future weeks stay "Coming Soon" until ready.
