Week 1, piece by piece

The hardest week, in five moves.

Most people stall in Week 1. Here's what each piece actually is, and exactly how you know it's done.

1 · Accounts + Repo

Create your GitHub account, make the repository, add the README. Done by hand on github.com, no prompts.

✓ Done when: the repo exists on GitHub with a README.

2 · Set up your workspace

Install VS Code and GitHub Desktop, clone the project to your computer, and add the Claude Code extension.

✓ Done when: the Claude sunburst opens in VS Code and responds.

3 · Build + deploy

Log in to GitHub, build your landing page, push it, and deploy to Vercel.

✓ Done when: your landing page is live on a Vercel URL.

4 · Give your app a database

Connect Supabase. Two connections: the MCP (Claude ↔ Supabase, to build tables) and the keys in Vercel (your live site ↔ Supabase).

✓ Done when: Claude can create tables AND the Supabase keys show in Vercel.

5 · Build your login

Add sign-up and log-in so your people have real accounts on your platform.

✓ Done when: a test account shows up in Supabase.

Make it feel alive

Always tell the user what's happening.

The #1 usability rule (Nielsen Group): visibility of system status. Keep people informed about what's going on, clearly and quickly. It matters double for AI apps, because AI takes a few seconds to respond.

A frozen screen doesn't say "loading." It says "broken."

Four things make an AI app feel trustworthy. Nail these first, the rest is polish:

Streaming Pivotal

The response appears word-by-word as it's generated, instead of making them wait for the whole thing.

You've seen it: Claude and ChatGPT "typing" the answer out live.

Thinking indicator Pivotal

The little dots or "thinking…" shown while the AI or an agent is working, so it doesn't feel frozen.

You've seen it: the three bouncing dots in any chat app.

Graceful fallback / retry Pivotal

When something fails, show a plain message and a way to try again, instead of crashing or going blank.

You've seen it: "That took too long, tap to try again." AI calls fail more, so this is a must.

Inline validation Pivotal

The error shows right at the field as they type, not after they submit.

You've seen it: an email with no "@" gets "Please enter a valid email" under the box instantly. Matters for logins and sign-ups.

Their takeaway, drop this into Claude Code and it audits your own build:

Copy this into Claude Code
Look at what I'm building and tell me where a user could be left staring at a frozen or blank screen. Then add proper feedback: stream the AI's responses so they appear as they're generated, show a "thinking" indicator while an agent is working, and give clear, plain-language error messages that say what happened and what to do next. Never let the user wonder if it's broken.
